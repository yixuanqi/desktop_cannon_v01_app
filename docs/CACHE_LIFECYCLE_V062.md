# Desktop Cannon V0.6.2 — 桌面图标缓存生命周期

## 范围 / 非目标

- 基于 V0.6.1 图标刚体物理 + V0.4 原版小炮素材，**不调整美术、弹道、炮闩、物理系数**。
- 只读 Windows Explorer 图标单元格、内存图标副本和背景贴片；**不移动图标、不写文件、不修改桌面布局**。
- 重点解决：分辨率/DPI/壁纸/图标位置变化后，旧的碰撞区、背景贴片或晚到的异步图片不应继续生效。

## 当前可观测环境与时机

| 触发 | 采集时机 | 原理 | 安全策略 |
|---|---|---|---|
| 托盘开启物理互动 | 立即查询环境、Shell 快照、预热 | `icon_environment` + `icon_snapshot` + `icon_visual_samples` | 缓存就绪前仅火星 |
| Tauri overlay Resize / ScaleFactorChanged / Moved | 事件后触发 | Rust `on_window_event` -> JS 事件；此外 JS `resize` | 第一时间取消飞散、清理旧图 |
| 显示器分辨率、DPI、工作区改变 | 轮询最多约 2 秒后发现，常见情形亦由窗口事件触发 | 重新从主显示器读取实际物理尺寸/原点/缩放/工作区，刷新全屏 overlay 尺寸 | 全量失效重建；过渡期间仅火星 |
| 静态壁纸切换、同一图片文件被更新 | 每约 2 秒查询 | `IDesktopWallpaper` 返回路径/模式，外加文件长度与修改时间 | 立即清除旧背景贴片并重采样 |
| 图标移动、添加、删除、网格尺寸变化 | Shell 每约 4 秒一次检查 | 位置快照 key：Explorer epoch、图标数、token、物理坐标、cell 宽高 | 布局变化时全量重建，防止 `cell:index` 复用造成错误图标 |
| Explorer 窗口/视图身份变化 | 下一轮 Shell 快照 | `explorerEpoch` | 清空图标碰撞快照及视觉缓存 |
| 手动关闭互动/隐藏小炮 | 立即 | 托盘状态回传 | 取消动画、删除内存副本与遮罩 |
| 采集失败 / 没有桌面前台权限 | 失败立即清理 | COM 或背景匹配失败安全降级 | 仅命中火星，不播放迟来的飞散 |

**重要限制**：本版没有订阅所有 Shell 变化通知，也没有读取每个图标的稳定 Shell item ID。仅替换同一网格位置上的图标且图标数量、坐标不变时，可能无法被位置签名发现。全量/单图标图片更新可留待后续增加 `SHChangeNotifyRegister` 等通知以及项目稳定 ID。本版优先保护「永不把过期图标贴片画到错误位置」。壁纸类型仍只支持原版 V0.6.1 已验证的静态 stretch/fill；其他类型安全降级。

## 更新原理

1. `icon_environment()` 在 Rust 中重新读取 **主显示器的实时几何** 和壁纸版本；壁纸 COM 查询在后台 STA 线程执行。
2. 环境指纹变化：`IconCacheLifecycle.revision++`，清空快照签名和动画；`IconIllusion.invalidate()` 清除缓存并使在途图片解码失效；`IconProbeRuntime.invalidate()` 丢弃候选碰撞矩形和正在执行的旧 Shell 快照。
3. 重新枚举图标，使用新的物理→overlay CSS 映射建碰撞区域；改变位置时重新预热图标。
4. `prepareVisualCache()` 的异步回调必须匹配启动时的 **环境指纹 + 快照签名 + revision**，否则结果丢弃，不允许旧图片复活。
5. 图片批次里的每个 token/物理矩形再次与碰撞快照比对，发现不符就清空并重新枚举，不生成飞散副本。
6. 热缓存仅在快照相同且图片已成功解码时复用。命中路径保持完全同步，无截图、编码或网络。

## 资源与性能

- 禁用时不运行 2 秒环境探测/4 秒图标探测。
- 环境探测只读取显示器元数据、壁纸路径、文件元数据，不解码壁纸。
- 图标位置相同且环境不变：不重复运行批量 PNG 截取/解码。
- 图标变化时采用 **安全的整批刷新**，目前还未实现按图标增量采样；避免在不稳定的 `cell:index` 身份下错误复用缓存。
- Rust 读取环境/图标/PNG 的耗时需在 Windows Release 实测，尤其 54 个图标及高 DPI 场景。

## 验收流程（Windows 实机）

先运行 `Windows验证V062.bat`，确认 `cargo check` 完成。然后运行 `Windows开发启动.bat`，右键托盘开启唯一的 `桌面图标物理互动`。

1. **首次预热**：等到出现“图标素材已预热 N 个”，打一个普通桌面快捷方式；确认命中即时启动，数秒内回位。
2. **移动图标**：在 Explorer 桌面拖动一个图标，4 秒后再次发射。只允许从新位置触发，旧位置不允许绘制遮罩。
3. **调整分辨率**：1920×1080 改为另一分辨率，等待环境更新（通常 2 秒内），旧动画立即取消，新分辨率下图标坐标准确、无墙纸残块。恢复 1920×1080 再测。
4. **修改 DPI / 缩放**：100% ↔ 125%，确认不发生双重缩放，重复步骤 1。
5. **换壁纸**：在支持的静态填充/拉伸图之间切换，2 秒后重新预热；替换期间不能显示旧壁纸补丁。
6. **Explorer 重启**：任务管理器重启 Windows 资源管理器后等待重新枚举；不能沿用旧视觉缓存。
7. **高频切换**：预热期间连续修改图标位置/壁纸/分辨率 3 次，最终只能使用最新一次缓存。不中断原版炮弹物理。
8. **关闭/隐藏**：飞散动画过程中关闭互动或隐藏小炮，遮罩与副本必须立刻消失；禁用时不再定期采集。

## 未验证 / 已知边界

- 当前构建环境不是 Windows，没有 Rust/MSVC 工具链。本轮已完成 JavaScript 回归与静态工程检查，**原生 Rust/C++ 编译、Windows 消息响应及透明窗口行为仍待实机验收**。
- 原位遮挡依赖 V0.6.1 的静态壁纸边缘匹配；动态壁纸、其他程序覆盖图标、复杂透明效果、非主显示器不承诺无痕飞散。
- `WM_DISPLAYCHANGE` / `WM_SETTINGCHANGE` 未直接安装低层消息钩子：使用 Tauri 窗口事件 + 2 秒环境指纹轮询兜底。故分辨率变化未必在事件同帧发现。
- 图标真实内容变化但位置与数量不变时，当前签名不足以保证即时更新；需要 Shell 项目稳定身份与变化通知。
- 自动化测试不代替真实 Windows GPU/Explorer 桌面验收。
