# Desktop Cannon V0.6 — 单图标视觉飞散实验 / 工程设计与验收

> **状态：实验版，未通过 Windows 原位遮挡验收。** 本轮是实际代码接入、纯 JS 测试、合成图像验证；不是已完成的 Windows 无痕飞散功能。保留 V0.4.1 美术/动画与 V0.5.3 Shell 检测。

## 1. 实验目标与硬约束

- 炮弹碰撞 Explorer 图标的候选单元格后，尝试让一个图标副本飞散、翻转、约 2.1 秒后恢复。
- Explorer 中的实际图标和文件**完全不移动、不删除、不写布局**。
- UI 透明特效层始终鼠标穿透，不能阻止原生操作；鼠标进入被遮挡图标区域时取消视觉假象。
- **只允许一个副本同时飞行**；用户主动关闭、切换前台应用或窗口隐藏应立即清理遮罩。
- 动态壁纸、多屏不同壁纸、无法精确还原背景、非桌面前台：**一律降级为已有命中火星**。
- 实验选项默认关闭；打开后自动启用图标命中检测，并关闭绿色调试框。

## 2. 运行架构

```text
Rust / Windows STA
  ├─ IFolderView GetItemPosition → 真实图标候选单元格（只读）
  ├─ IDesktopWallpaper GetWallpaper + GetPosition → 静态壁纸来源/填充方式
  ├─ BitBlt (最多 256×256) → 命中单元格的屏幕像素（RAM）
  ├─ 壁纸填充区域映射 → 原位背景图
  ├─ wallpaper-pixel difference → 透明图标副本（含近似文字）
  └─ 安全匹配判据（边界像素匹配 ≥88%，平均误差 ≤17）
              ↓ Result<VisualSample,Error>
Tauri bridge（只在用户开启实验时调用）
              ↓
Canvas IconIllusion（单个）
  ├─ draw background over stationary icon
  ├─ draw animated PNG copy on top
  └─ after 2.1 s / safety abort → stop both drawings
```

**安全限制：** 目前识别的是 `GetSpacing()` 候选网格而非 UI Automation 精确图标/文字边界，因此可能隔空命中。视觉取样必须使用最新 Shell 快照的同一 token；本轮尚未实现稳定 ID 与精准可见矩形。

## 4. 最重要的限制：为什么不能承诺“无痕”

Windows Explorer 没有给普通程序一个可靠的“仅隐藏这一枚图标但保留原位置、文字”的简单可用接口。当前方案是**视觉覆盖**：使用匹配的静态壁纸覆盖真实图标，再移动自己绘制的图标副本。

这意味着：

1. 屏幕像素与底层静态壁纸**必须匹配**。动态壁纸、Windows Spotlight、壁纸缩放方式不受支持或前景软件覆盖会被拒绝。
2. 捕获时全屏特效层可能还残留炮弹或烟雾，导致副本带入噪声。第一版仅做严格的壁纸边缘判据；**中心区域污染仍可能发生，需要实机截图检查**。推荐下一阶段改为蓄力开始时预采集，避免在命中后截图。
3. 图标文字的抗锯齿、阴影和背景融合无法从单次屏幕截图完美反解。细节可能有毛边。
4. 透明 Canvas 的遮罩本身置顶，不能自动知道全部非前台窗口是否遮住图标。本轮仅以 Desktop/本进程前台作为保守门控，并每 200 ms 检查；不是完整窗口遮挡检测。
5. 真实图标没有消失，点击仍传给 Explorer；鼠标进入遮挡区域立即取消视觉特效，**不能保证鼠标第一次点击前就取消**。
6. 获取到的只是单图标单元格；Windows 多显示器、DPI/色彩管理和不同壁纸均须实机专门验证。

以上任何一条失败时，**保留已稳定的炮弹与命中火星，不应该为了动画而关闭真实图标功能**。

## 5. Windows 实机验证步骤

1. 关闭所有旧版 Desktop Cannon 进程，解压独立文件夹。
2. 双击 `Windows验证V06.bat`，先运行 JS 测试，再让 Cargo 检查原生模块。**Windows 原生代码尚未在交付环境编译过**；若失败，请提供编译错误日志，不要继续验收。
3. 用 `Windows开发启动.bat` 启动 Tauri。
4. 先确认原版小炮与炮弹正常。**只在静态图片壁纸且单显示器**下做实验。
5. 右键系统托盘，选择 **「单图标飞散实验（默认关闭）」**。该操作自动打开图标命中并关闭绿色调试框。
6. 朝左侧某个普通快捷方式发射炮弹（不要先试回收站、此电脑）。
7. **成功路径（仍需人工验收）**：原图标由原位壁纸覆盖，视觉副本飘起约 2 秒回到原位；无图标位置变动，动画结束没有残影。
8. **失败路径**：不飞散，仍有火星；屏幕右上角短暂显示 `WALLPAPER_MISMATCH / WALLPAPER_INFO / DESKTOP_NOT_FOREGROUND` 等原因。右键托盘打开 **「V0.6 · 打开独立诊断窗口」** 可查看“最近视觉取样”。
9. 试验过程中将鼠标移入该图标原始区域，或切换到其他软件；遮罩应取消。
10. **立即退出实验**：再次点击托盘「关闭单图标飞散实验」，原版小炮和命中火星仍正常。

## 6. 验收关卡（不要跳过）

- M0/M1/M2：现有物理、Shell 枚举与命中已经得到用户 Windows 截图验证。
- M3-A：原位贴片背景能否在用户静态壁纸上**像素级对齐**？截图 200% 检查文字/线条/色块；未过不能宣布 M3 完成。
- M3-B：抠出的视觉副本是否有可见背景方块、重影或炮弹/烟雾污染？未过不能宣布可发布。
- M4-A：仅单图标飞散、回位、关闭即清理。纯 JS 单测通过，Windows 视觉待确认。
- M4-B：切换前台、鼠标移入、Explorer 重启、桌面图标移动后的异常清理与兼容性。

## 7. 性能与隐私

- 空闲时不执行任何图片捕获。用户主动开启实验并命中图标后才调用。
- 一次取样不超过 256×256 像素，PNG 保留在运行时内存中，不写入文件、不上传网络。
- 静态壁纸读取用于局部背景匹配；若路径无法访问或解码失败立即拒绝。
- 仅一个活动飞散对象，Canvas 只在有炮弹或飞散动画期间持续重绘。
- 真正的 Windows CPU/内存/GPU 压力未测量，不能把 JS 测试作为资源占用基准。

## 8. 下一阶段建议

如果用户实机里 `WALLPAPER_MISMATCH` 很常见，不要降低阈值强行显示假动画。更可靠的选择是**在拖动炮闩开始时，从真实桌面提前采集候选图标**，并考虑通过 UI Automation 获取精确的图标图像和文字边界。待取得高质量贴图后再做多图标连锁与丰富的飞散物理。
