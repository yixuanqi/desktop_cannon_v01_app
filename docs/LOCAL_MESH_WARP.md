# 可复用的 2D 局部网格变形：平滑位移场 + 预计算帧

> **项目应用**：桌面小炮 V0.4。**技术范式**：单张高质量 RGBA 原画 → 连续的局部位移场 → 预生成带 Alpha 的动画帧 → UI 随输入选帧，同时更新交互锚点。这不是图像生成，不是 3D，也不是刚体旋转。

## 1. 为什么采用

原始 V0.1.1 是一张整体绘制的漂亮小炮，炮口、奶油白炮身、兔子木轮、草地之间自然融合。直接裁出炮管再刚性旋转，会把**原来被遮住、其实没有画出的下腹**暴露出来，出现缺口、台阶与边缘毛刺。程序化 SVG 重绘虽能获得完整部件，却牺牲了原画的风格。

因此采用**小角度局部变形**：**保留整幅图片，不划分硬边界**；炮口运动幅度大，兔子木轮附近变形权重低，草地几乎不变。经初步视觉验证的范围是 **30°～38°**，34° 为原图原样；不保证适用于更大角度，也不能替代真实遮挡结构。

## 2. 算法数学原理

在原始图像像素坐标系中，X 向右、Y 向下，旋转参考点为 `c=(280,216)`，期望的姿态变化为 `θ=(angle-34)π/180`。

### 2.1 每像素的影响权重

采用几个平滑衰减函数相乘，权重 `w(x,y)∈[0,1]`：

```text
S(z) = 1/(1+exp(-z))
U = S((242-y)/16)               // 保护下半部
L = S((x-49)/18)                // 左侧柔和退出
R = S((381-x)/18)               // 右侧柔和退出
G = S((294-y)/8)                // 草地保护
W = exp(-0.5*((x-279)^2/67^2 + (y-258)^2/44^2)) // 木轮保护
w = U * L * R * G * (1 - 0.92*W)
```

数字均为**当前 480×350 小炮源图专属参数**，在新项目使用时需要重新校准。重要的不是这些数字，而是：主运动区权重大、受保护区权重小、各区之间连续变化。

### 2.2 小角度位移

对图像中每个目标像素 `(x,y)`，定义平滑的位移场：

```text
dx(x,y) = -θ * (y-cy) * w(x,y)
dy(x,y) =  θ * (x-cx) * w(x,y)
```

旋转分量在 `w=1` 时近似为小角度旋转，在 `w≈0` 时像素几乎不动；介于两者之间则连续变形。这个位移并非严格刚体旋转，不保长度、面积，也可能使某些绘制元素轻微拉伸。`θ` 小时视觉上通常较自然。

### 2.3 逆向映射（避免采样空洞）

不能把原像素直接搬到目标画布后期待每个目标像素都有颜色。用**逆向采样**对目标像素取源图颜色：

```python
source_x = X - dx(X,Y)
source_y = Y - dy(X,Y)
output = cv2.remap(premultiplied_rgba, source_x, source_y,
                   interpolation=cv2.INTER_CUBIC,
                   borderMode=cv2.BORDER_CONSTANT)
```

这里 `dx,dy` 在**目标坐标**计算，所以用于鼠标点击、炮口位置等交互锚点的正向位置，需要另外解方程 `destination-displacement(destination)=source`，不能直接套刚体旋转矩阵。运行时用 7 次固定点迭代求解，代码在 `web/js/mesh-warp.mjs`。

### 2.4 预乘 Alpha

直接对普通 RGBA 四通道插值容易产生透明黑边/白边：因为透明像素的 RGB 可能为黑色。正确做法先：

```text
RGB_premul = RGB * Alpha / 255
```

再将 `RGB_premul` 与 `Alpha` 一同重采样，最后在 `Alpha > 0` 时恢复：

```text
RGB = RGB_premul * 255 / max(Alpha, 1)
```

Alpha 为 0 的 RGB 清零。为了更高的边缘质量也可以对浮点通道进行完整规范化；对多张压缩 PNG 的时间序列，始终使用同一处理策略避免闪边。

## 3. 小炮项目中如何应用

| 项目参数 | 数值/方式 |
|---|---|
| 原始图 | `web/assets/cannon_base.png`，480×350 RGBA |
| 角度 | 30°～38°，34° 作为原始静止姿态 |
| 采样间隔 | 每 0.5°，共 17 帧 |
| 默认源图 | `pitch_08.png`，与原画 RGBA **逐像素一致** |
| 独立运动件 | 红色炮闩与弹簧，仍按鼠标拖动拉伸 |
| 鼠标操作 | 向右蓄力，上下微调俯仰，按住炮身移动窗口 |
| 炮弹物理 | 使用当前量化角度 + 变形后的炮口锚点 |
| 其他结构 | 图像整体局部平滑变形；没有硬切边界 |

帧生成：

```bash
python -m pip install numpy opencv-python Pillow
python scripts/generate_mesh_frames.py
npm test
npm run preview
```

项目中：`web/js/aim.mjs` 将角度量化为 0.5°，`web/js/mesh-warp.mjs` 为原图和交互锚点计算同一位移场；`web/js/geometry.mjs` 在发射时求出被位移后的炮口坐标；`web/js/cannon.mjs` 根据角度替换帧图片、让炮闩轴跟随炮尾，并继续调用原有的事件和物理系统。`web/assets/mesh/mesh_rig.json` 记录素材与变形参数。

**务必确保画面角度、发射角度、炮口生成点一致。** 不能只做选帧而不更新实际子弹生成位置。

## 4. 如何复用到其他项目

此思路适用于“已经有一张很好看的整体插画，希望只做小幅度运动、不愿重新分层绘制”的情况。例如：

- **桌面植物**：叶尖微晃、花朵点头、短暂受风；把花盆、泥土区域的权重压到 0。
- **桌面宠物**：耳朵轻晃、身体呼吸、帽子轻摆；保护脸部和脚部的形状，避免五官变形。
- **游戏道具**：旗帜轻摆、翅膀轻微扇动、柔软树枝摆动。
- **插画 UI**：图标轻微弹性、布料或绳索的小范围动态。

### 复用步骤

1. 选原始 **RGBA 整体图**；检查透明边缘，尽可能从高分辨率源图开始（不是设计海报截图）。
2. 标出**运动主体**、**需要保护的区域**、**过渡区**以及近似**转轴**。
3. 修改 `mesh_rig.json` 中的画布尺寸、pivot、角度范围与 `influence` 权重参数。注意 `influence` 的坐标默认以**源像素**计量，尺寸改变时要整体等比例缩放。
4. 用 `generate_mesh_frames.py --source <sprite> --out <folder> --rig <rig.json>` 预生成帧。
5. 以原始姿态和上下两端姿态，在浅色/深色背景上 200% 放大看：眼睛、边缘、连接部位、花草等有没有拉扯变形。
6. 把运动锚点（如炮口、手、叶尖）用**同一个位移场**计算位置，确保物理和视觉相符。
7. 适合少量姿态时使用**预计算 PNG**，复杂实时变形才考虑 WebGL/OpenGL 顶点网格或位移纹理。

### 何时不适合

- **大幅真实转动**、翻面或突然暴露背面：单张原图没有不存在的隐藏面，数学变形不会凭空生成背面。
- **高度刚性物体**需要严格保持圆形、长度和透视：非刚性变形可能把结构拉弯。
- **交互必须像素级精准**的机械运动，或者需要强烈前后遮挡变化：应制作真实分层/3D 模型。
- 重复编辑的原图本来边缘肮脏：网格变形会保留甚至传播已有毛刺，需要先清理原图。

## 5. 性能和工程策略

目前用**离线 Python**生成 `17×480×350` 的 PNG。单张完整 RGBA 解码缓冲约 `480×350×4 = 672000 bytes`（约 0.64 MiB），17 张像素缓冲合计约 10.9 MiB（不含 WebView2 缓存和纹理副本）。浏览器切换 `img.src`，**运行时不需要 OpenCV，也不会每帧重新执行整幅重采样**。

优化建议：
- 限制活动范围，不需要 60 FPS 都用新的 PNG；0.5° 是有意的视觉/资源折衷。
- 初次进入先加载中性帧，空闲时预热其他帧。
- 没有炮弹时让全屏 Canvas 停止 RAF；静态帧不需要持续重绘。
- 纹理内存比 ZIP 文件大小更有意义；正式资源占用仍要在 Windows Release 版本中量 CPU/GPU/内存。
- 若有大量角色且帧数多，考虑纹理图集、SpriteAtlas 或 GPU 实时变形（但必须复核边缘质量）。

## 6. 视觉与功能验收

**必须自动检查**：帧数和索引、尺寸、透明通道、默认角度与原图逐像素一致、帧可解码、变形参数与 JS 一致、发射角度与实际显示帧一致。

**必须人工/截图检查**：30°/34°/38° 的深浅背景合成、木轮是否过度拉扯、草地是否乱动、炮口是否明显变形、炮闩是否脱节。此前出现的毛刺、缺口、重叠“金色台阶”不能被脚本通过替代视觉验收。

**无法替代的验收**：Windows WebView2 的真实透明窗口、DPI 缩放、浏览器叠层、鼠标穿透、实际 GPU 占用，这些仍需要 Windows 实机。

## 7. 相关文件

```text
scripts/generate_mesh_frames.py     离线生成和透明边缘处理，可复用
web/assets/mesh/mesh_rig.json       当前素材变形参数
web/assets/mesh/frames/            17 张实际透明动画帧
web/js/mesh-warp.mjs                浏览器端权重/交互锚点同源变换
web/js/geometry.mjs                 炮口和炮尾精确交互位置
web/js/aim.mjs                      角度限制与量化
web/js/cannon.mjs                   UI 选帧、炮闩跟随和发射
scripts/validate_mesh.py           图片与像素回归验证
```

**抽象总结**：`保护区权重 × 运动区位移场 × 预乘 Alpha 逆向采样 × 同源锚点映射 × 多姿态验证`。这个模式适用于许多桌面玩具的低成本、低幅度、保画风动画。
