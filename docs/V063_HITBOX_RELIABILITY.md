# Desktop Cannon V0.6.3 — 图标命中区域、延迟和新旧进程排查

## 实机反馈与证据

1. 用户屏幕左上角仍显示 `V0.6.0 图标候选就绪`。V0.6.2 工程没有绘制这行文字和绿色整格框的代码。因此需要排查遗留进程 / 启动目录，而不是只根据旧网格评价新版本。
2. 桌面日志出现 `WALLPAPER_MISMATCH:border=0.87,mean=6.1`。这是**图标视觉采样失败**，不等于扫掠碰撞失败，也不允许通过强行放宽背景容差来伪造无痕飞散。
3. 旧版使用 `GetSpacing()` 的整个 95×123 单元格做碰撞，空白区触发假命中，边界不对应实际图标。
4. 旧版按图标 token 做 500ms 全局冷却，两颗炮弹快速打同一图标时第二颗会被忽略。
5. 旧版以前台是不是桌面为全局筛选，窗口焦点变化可能让所有碰撞目标消失。

## V0.6.3 实现

- 增加 Tauri Single Instance 插件（对同一 App ID 的**新版进程**生效）。启动脚本额外检查老版本 `desktop-cannon.exe`，让用户选择是否关闭；绝不未经确认关闭进程。
- 主显示器只读 Shell 枚举保持不变；新增 `IFolderView2::GetViewModeAndIconSize()` 查询图标尺寸。使用`GetItemPosition + 图标尺寸 + 小容差`构造图标**图像**命中区域，而非整个网格。这里仍是估算，不声称像素级精确。UIA / 真正边界仍是后续可选验证。
- 碰撞冷却按 `(shotId, iconToken)` 而非只按图标；一个炮弹不会在多个物理子步上重复命中，同一位置的新炮弹可立即再次命中。
- Windows 全局前台标记不再清空碰撞矩形；但视觉截屏和遮挡仍采用保守的前台安全校验（否则会错误遮住其他应用）。可见性应在下一阶段按单图标和窗口遮挡单独判断。
- 图标视觉预热改为部分成功亦可使用，不再因一张图片解码失败丢弃整个有效缓存。命中没有素材时立即播放火星，不延迟补播图标。
- 布局复查间隔 2 秒；快照过期（6.5 秒）后拒绝使用陈旧坐标。现有壁纸/显示环境缓存代次隔离继续保留。
- 特效窗口启动后 7 秒短暂显示 `Cannon V0.6.3`，方便确认是否旧版混跑，之后淡出。

## 安全边界

- **不移动或删除真实桌面图标。** Shell GetItemPosition / GetViewModeAndIconSize 都是只读。
- **`WALLPAPER_MISMATCH` 不会自动降阈值通过。** 无法安全还原壁纸的图标只得到即时碰撞火星，不会产生冒充无痕的飞散动画。
- 仅对主屏，DPI、Explorer重启、多窗口遮挡仍需要实际 Windows 验证。
- Windows 原生 Rust/C++ 未在当前 Linux 环境编译；必须执行 `Windows验证V063.bat` 后才能判定编译通过。

## 验收步骤（先关闭旧进程）

1. 从任务管理器确认没有旧的 `desktop-cannon.exe`。运行 `Windows开发启动.bat` 时会列出残留 PID，并在用户确认后才关闭。
2. 启动后观察屏幕右下角短暂的 `Cannon V0.6.3` 标识；**如果仍看到 V0.6.0 的绿色整格框，应先退出残留进程，不要继续比较。**
3. 打开桌面图标物理互动，选一个普通图标：炮弹从图标边缘划过应有火星，经过网格空白区不应命中；快速连发两颗都应分别触发命中。
4. 观察预热状态。`WALLPAPER_MISMATCH` 时不得等待并在数百毫秒之后补播飞散；只应立即显示火星。
5. 修改桌面图标排列或分辨率，待新缓存完成后重试；检查位置和素材一致性。
6. 性能与用户体验：1080p Release 下检查命中反馈同帧或下一帧出现，注意当前还未实机证明；连续运行 15 分钟不出现残留壁纸贴片。

## 下一阶段而非本轮承诺

要做到**真实精确图标矩形**：在 Windows 端通过 UI Automation 的 `BoundingRectangle` 实测，匹配 Shell 项目；再独立验证窗口遮挡和图标标签。仅凭 `IFolderView::GetSpacing()` 不够。

要做到**所有图标稳定飞散**：还需要解决复杂壁纸与实际桌面画面的像素匹配，以及图标素材获取方式；碰撞通过不代表无痕动画通过。该阶段不应该盲目放宽 `borderMatch` 阈值。
