# Desktop Cannon V0.6.4 — 多图标连锁命中与落地停留

## 本轮目标

在 V0.6.3 的 Windows Shell 只读图标枚举和 V0.6.1 实验物理基础上，**修复“每次只能打落一个图标”**，改善图像与文字混在一起旋转的问题，并让已落地的图标**稳定停留 5–8 秒后**才弹性返回原位。

> 不修改 Explorer 真正的图标位置、不移动/删除文件、不改变桌面布局。所有飞行对象均为透明 Canvas 上的视觉副本。用户停用功能、环境变化或安全校验失败，必须立即移除遮罩和副本。

## 原问题的根因

1. 旧 `IconIllusion.active` 只能保存一个运动对象，`onHit()` 遇到已存在的 `active` 就拒绝所有后续命中。
2. 旧 `firstIconHit` 一次线段只返回第一个碰撞点，即使同一物理步跨越多图标也只上报一个。
3. 旧图标副本通过对**图标 + 名称的整个 Shell 网格单元**做屏幕差分获得，导致文字、缩略图边缘、背景片段被一起转动。
4. 旧 `flightSeconds=0.92` 导致快速开始阻尼弹簧回位，图标没有在地面停留的时间。
5. 壁纸与屏幕采样不一致时 `WALLPAPER_MISMATCH` 安全拒绝；即使物理碰撞成立，也不能保证有可用于飞散的视觉缓存。

## 本轮实现

### 1. 多个独立刚体

`web/js/icon-interaction/illusion.mjs`

- `activeByToken: Map<string, PhysicsState>` 代替单个 `active`。每个图标可以独立飞行、翻滚、弹跳、等待、回位。
- 最多同时运行 12 个图标（显存与安全防护的实验上限）；达到上限后仍显示命中火星，但不新建副本。
- 同一个真实图标处于飞行/停留/回位时不重复从原位置生成副本。其他图标、其他炮弹继续正常互动。
- 严格按全图标的背景遮罩先绘制、全部飞行精灵后绘制的顺序，避免某个图标的原位遮罩擦掉另一个飞行图标。
- Windows 前台变化、鼠标进入任何一个被遮挡的原位矩形时，批量检查立即撤销整个互动会话，优先保护正常桌面操作。

### 2. 炮弹沿途多目标命中

`web/js/icon-interaction/collision.mjs` 增加 `allIconHits()`，按线段接触参数 `t` 排序，结合 1/120s 的实际炮弹物理子步检测。

`web/js/icon-interaction/runtime.mjs` 遍历所有新接触的候选，而不是只处理 `firstIconHit`。去重键为 `(shotId, token)`：同一颗弹不会多次击中同一图标；不同炮弹可击中不同目标。正在飞散的图标不再因其旧“家位置”触发幽灵碰撞。

**注意**：只有炮弹实际扫掠的 AABB 图像估算区域才算命中；它不会把屏幕上直线附近全部图标都自动打落。

### 3. 文字与图标贴图分离

`src-tauri/src/icon_visual.rs` 依然安全地读取内存中的屏幕图像与静态壁纸，校验壁纸一致性，但**只从完整图标网格内部的图像方形区域提取会运动的 RGBA sprite**。文字不再被纳入飞行副本。原位的文字在动画期间由壁纸贴片暂时遮挡，回位后完整显现。

新增 `imageLeft/imageTop/imageWidth/imageHeight`（相对于网格单元格的**近似**图像边界）并在 JS 中转成物理接触范围。落地碰撞使用真实运动图像的下缘，而不是整格的底边，从而避免悬浮在地面上方几十像素。

**局限**：Windows Shell `GetItemPosition + GetViewModeAndIconSize` 仍不能提供精确到每个异形图标的透明像素边界。对于大缩略图、自定义图标、缩放比例和双行名称，仍要在 Windows 实机检查。不支持像素级分割保证。

### 4. 落地后 5–8 秒再返回

状态机：`flight → rest → return → done`。

- `flight`：按炮弹速度得到初始冲量，重力、边界碰撞、速度衰减与偏心角速度均保留。
- `rest`：图标真正触地并稳定后开始计时。持续 `5.00–8.00 s`；同一 token 通过稳定哈希生成同一等待时间，便于复测。图标稳定停留，角度缓慢归正，**不提前返航**。
- `return`：弹簧阻尼把图标从当前位置拉回原位；完成后撤销该对象原位置的壁纸遮罩。
- 最长生命周期 18 秒，避免特殊物理状态无限占用缓存。最多 12 个图标独立计算与渲染。
- 停留时可以继续发射炮弹击落其他图标，不会清除已有落地对象。

### 5. 截图采集机制与第三方应用图标

当前实现不按名称做 AI 分类，也不需要知道是 Chrome、用户自研小工具还是开源软件。原生 Shell 枚举提供图标所在网格/大小，预热阶段 `BitBlt` 读取可见像素，再与当前静态壁纸逐像素求差来构造图标图像。

所以它对**所有来源**的图标使用同一条路径；但墙纸匹配失败、图标缩略图带复杂纹理、交叉重叠的文字、截图中存在悬浮窗口等情况，会触发素材不可用。命中火星继续触发，但不应延迟补播，也不放宽壁纸安全阈值假装成功。

如果希望对自定义 `.exe` / `.lnk` 获取真正无背景图标，后续可研究 Shell Item 图标提取与 Windows UI Automation 图标/标签边界，不应自行猜测软件类型或私自读取文件内容。

## 回归与验收

已通过 Node.js 自动化测试：见 `tests/icon-v064-multi.test.mjs`，覆盖：

- 单炮弹命中多个不同图标，同弹同图标去重
- 多炮弹命中后多个图标并发飞散，落地对象不会被下一炮移除
- 5–8 秒触地停留，停留后才开始弹性回位
- 按**图像区域**而不是含文字的网格底部进行地面碰撞
- 原位遮罩绘制顺序和关闭功能时全部清理
- 同一图标飞走后避免在旧位置重复碰撞
- 12 个并发上限和缓存失效保护

### Windows 实机验收要求（当前环境未完成）

1. 启动 `Windows验证V064.bat`，确认 Windows Rust/MSVC 原生编译成功。
2. 开启唯一托盘功能「桌面图标物理互动」，先等待显示成功预热的数量。
3. 用一颗满蓄力炮弹沿图标密集列飞行；确认可以打落多个**实际相交**且**已成功预热**的图标。
4. 在一个图标落地后的 5 秒内继续移动炮身发射，确认可以再打落其他不同图标。
5. 检查双行名称、自研 EXE 快捷方式、文件缩略图不再随图标旋转或被切下一块文字。
6. 切换桌面壁纸、显示分辨率或关闭互动开关，确认所有现有遮罩立即消失。
7. 快速发射、连续开关与 Explorer 重启，确认无残影、无卡顿、无文件位置变化。
8. 核对是否仍有 `WALLPAPER_MISMATCH`。不通过时只显示火星，不能把它作为飞散验收成功。

## 未实现或暂不承诺

- 图标彼此之间的真正刚体碰撞，或一个飞散图标再撞飞另一个图标
- 文字逐字淡出、图标外轮廓级命中、文件缩略图语义解析
- 任意动态壁纸、多显示器、全屏游戏上无痕遮挡
- Windows 端到端自动截图与 Windows Release 性能数据（需实机）
